Why you couldn't continue the 364 MB file

FFmpeg was killed SIGKILL -9 mid-encode. MP4 moov atom is written at the end — a killed file has no index and is unplayable. No tool can resume it. The chunked method fixes this: each segment is finished + flushed to disk. If the job dies at seg 18/45, restarting skips segs 0–18 and continues at 19.

/tmp/segments-chunked/seg00.mp4 → seg44.mp4 (each <6 MB, ultrafast crf23)

How this page auto-renders

  1. Loads parts-manifest.json (durations + URLs)
  2. Fetches chunks as blob in order, caches in IndexedDB (so refresh = resume)
  3. Plays sequentially: ended → next src (frame-accurate because xfade already baked inside chunks)
  4. Optional: stitch all blobs with ffmpeg.wasm concat demuxer → single 20-min MP4 download
